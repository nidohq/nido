Proposed durable-address mode

G remains the receive address. Rotate access key U without moving funds; change delegated policy in C separately.

G is an account identity. U is a replaceable signer. The original address/master key B has weight zero. F is a separate fee account and is never a signer on G.
Important boundary: U has threshold authority over G in this profile. It can spend directly; C is not an unavoidable on-chain gate. An “approve-only G” restriction remains an open design problem.

Reviewed authority kernel · proposed wallet integration

Recover access without changing G

  1. Exact authorityU alone or S + R meets the threshold. S or R alone does not.
  2. Safe key replacementValid rotations preserve the full account reference, thresholds and untouched signers; the retired key loses its role weight.
  3. Explicit loss boundaryIf U and either S or R are unavailable, the remaining evidence cannot form a quorum.

Read F and its registered budget. No refill is needed while the balance is sufficient.

02 · Refill

Approve C’s refill call

The budget rereads F’s balance and sends target − balance only to F, if the remaining cap covers it.

03 · Continue

Wait, then run the action

Confirm the refill before preparing the action. F pays the native network fees.

F must be funded before it can pay for a refill. Top-ups still need passkey approval. The cap covers this deployment’s refills, not initial funding or other deposits; it is not a ledger-enforced “fees only” restriction on F.
