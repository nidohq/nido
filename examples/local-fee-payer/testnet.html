What you will see

  1. Enroll once. Create a passkey. The wallet deploys your test account and funding budget, using Friendbot-funded U as the demo treasury.
  2. Approve an action. A low F balance first triggers a separate passkey-approved refill. Its lifetime cap is 0.15 XLM.
  3. Inspect the receipts. F signs fees locally. Each action increments an on-chain counter; repeat it to see another bounded top-up.

Setup can take a minute. If interrupted, retry with the same passkey: deterministic deployment addresses reuse the existing budget and spent counter.

The boundary this demonstrates

C’s native Perch rule authorizes the call. An immutable funding component sends XLM only to registered F within its cap. The wallet checks the exact transaction before releasing U/F signatures.

The refill planner and cumulative trace are formally proved. The browser, WASI host and contract integration are tested/trusted. An exported seed or compromised wallet host could still sign as F outside this path. Initial funding and other deposits are outside the refill cap. Testnet resets or expired contract state may require maintenance; no budget is silently replaced.
