# Supply chain and toolchain provenance

Every third-party input, how it is pinned, and what is still loose. The goal:
an auditor can account for each input and rebuild each artifact.

## Perch (`vendor/perch` submodule)

| Item | Pin | Notes |
| --- | --- | --- |
| Source | `https://github.com/stellar-registry/perch.git`, branch `fm/perch-epic99-deploy-p8`, commit `836fdc9` | Git submodule (`.gitmodules`). The commit is what counts; the branch only names where it came from. |
| Deployment manifest | `vendor/perch/deployments/testnet.json` at that commit | Every deployed contract's wasm hash, content address, registry, and build pins, plus the Perch commit (`aa5a78f`, clean) and toolchain (rustc 1.97.1, stellar 27.0.0, scaffold 0.0.27) that built them. |
| Deployed wasm | `just perch-infra` runs `vendor/perch/scripts/fetch-infra-wasm.sh --stack` against the manifest | Fetches each contract from the chain by the manifest's address (the account by hash) and refuses it unless its sha256 matches and the address is the content address of that hash under the manifest's registry. Nothing is resolved by name. The tests run these bytes, and the factory embeds the fetched `perch-account`. |
| Pin cache | Same script | Fills `crates/perch-smart-account/wasm/` (registry id, compiler, interpreter, spending limit), which the account's native crate reads at build time, from the same checked bytes. |
| Rust crates | Path dependencies on `vendor/perch/crates/*` (root `Cargo.toml`) | Clients, types, and the native prover for the tests. One checkout, so Perch's types unify with Nido's; Nido's `Cargo.lock` resolves their dependencies. |
| TypeScript | `@stellar-registry/perch` 0.3.1 and `@stellar-registry/perch-zk` 0.1.0 as npm workspaces from the submodule (root `package.json`) | The SDK pins these exact versions so npm links the workspace copies, not the registry's `@stellar-registry/perch@0.3.1`, which lacks the recovery schema and encodings. perch-zk's indexer has an optional peer dependency on `@stellar/stellar-sdk` 17, which npm installs as a nested second copy; Nido imports only perch-zk's proving entry, so it isn't bundled. |
| Contract clients | `packages/contract-bindings/perch-*` | Generated by `stellar contract bindings typescript` from the deployed wasm (`just bindings-perch`). `private`; replaced by Perch's `@stellar-registry/perch-contracts` once Perch publishes it. |

**These pins move to published packages once Perch merges and publishes the
release**: its crates and npm packages from their registries, and its wasm by
the hashes already in the manifest.

## Proving toolchain

| Tool | Pin | Enforced by |
| --- | --- | --- |
| `nargo` | `1.0.0-beta.9` | `vendor/perch/scripts/zk-toolchain.sh` downloads the GitHub release and checks a pinned SHA-256; the prover refuses other versions. |
| `bb` (native) | `0.87.0` | Same script and checks. |
| `@aztec/bb.js` | `0.87.0` | perch-zk's `package.json`, resolved in Nido's root `package-lock.json`. Proofs from any other version fail at the pairing check. |
| `@noir-lang/noir_js` | `1.0.0-beta.9` | Same. |
| Reference string | Downloaded by bb.js from `crs.aztec.network` at proving time | Not pinned. A substituted file makes proofs fail; self-hosting it with a checked hash is open (MAINNET_READINESS E4). |

The adapter embeds NethermindEth's UltraHonk verifier, audited by
OpenZeppelin and vendored in Perch
(`vendor/perch/vendor/ultrahonk-soroban-verifier/NOTICE`), plus Perch's
unaudited delta for Barretenberg's zero-knowledge flavor
(`UltraKeccakZKFlavor`), with the VK compiled in. `just gen-zk-fixtures`
re-proves Nido's fixtures with this toolchain; zero-knowledge proving is
randomized, so CI requires every fresh proof to verify and every
`fixture.json` (statement digest, root, nullifier) to stay the same.

Nido's former verifier (a vendored, unaudited bb 3 port of
`rs-soroban-ultrahonk`), its drift guard, and its nargo beta.18 / bb 3
nightly toolchain are gone with the contracts that used them.

## Build toolchain

| Tool | Pin | Status |
| --- | --- | --- |
| Rust | `1.96.0` (`rust-toolchain.toml`, CI `dtolnay/rust-toolchain@1.96.0`) | Pinned. Builds Nido's wasm; Perch's wasm isn't built here (the manifest records Perch's own toolchain). |
| `stellar-cli` | `cargo install --locked stellar-cli`, unpinned | **Gap.** The CLI writes its version into each wasm's metadata, so the wasm hash depends on it. Pin it and record which version built each deployed wasm (the testnet factory: 27.0.0). `just perch-infra` also uses it to fetch Perch's wasm, whose bytes are checked by hash. |
| `stellar-scaffold-cli` | `cargo install --locked stellar-scaffold-cli`, unpinned | **Gap.** Builds Nido's own wasm (`just build-contracts`) and records itself in the wasm metadata. |
| `[profile.contract]` | committed (`lto`, `codegen-units = 1`, `panic = "abort"`, `overflow-checks`, `opt-level = "z"`) | Good for reproducibility. |

A local build's wasm hash also depends on the machine (paths in panic
messages, CLI metadata). Tests that bind a wasm hash into a proof therefore
use a committed wasm (`crates/integration-tests/fixtures/upgrade-target.wasm`).

## npm

Lockfiles: the root `package-lock.json` (workspaces: SDK, frontend, wallets-kit
module, contract bindings, the example dApp, Perch's two packages), plus
`packages/passkey-sdk/package-lock.json`, the `infra/*` workers' locks, and
the relayer channels plugin's `pnpm-lock.yaml`.
`@stellar-registry/perch-interpreter` comes from npm, with a root `overrides`
entry keeping it on the workspace's single `@stellar/stellar-sdk`.

The wallet's `@stellar/stellar-sdk` (15.1.0) decodes XDR from before
protocol 27: it has no `AddressV2` or `AddressWithDelegates` credentials, and
no released `@stellar/stellar-base` (15.0.0) does yet. Decoding anyone else's
transaction that uses them throws. `getLatestLedger()` decodes the tip's
whole close meta, so the wallet reads the tip from the RPC's raw answer
instead (`latestLedgerSequence`). The example dApp still calls
`getLatestLedger()`.

`@nidohq/passkey-sdk` is not publishable while it depends on the private
`@nidohq/perch-*` clients. It becomes publishable when those are replaced by
Perch's published `@stellar-registry/perch-contracts`.
